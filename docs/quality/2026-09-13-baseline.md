**Result: useful for checked single-column reading; not yet reliable for unattended formula/table extraction or multi-column research.** This is a small acceptance baseline, not a broad accuracy benchmark. Content defects remain visible even when API integrity checks pass.

Product baseline: `95a404d` (stages one through three). Corpus provenance, source hashes, physical page selections, reproduction commands and manual rubric are in [the corpus guide](README.md) and [manifest](corpus.json). All runtime files were isolated from the user's workspace.

One of four text cases passes all measured checks; three have content failures. The fifth case confirms an explicit OCR blocker and receives no transcription-quality score.

## Formula inspection

The rendered NIST physical page 14 contains equations B-1 and B-2. Compared with that image, the extracted text loses important mathematical structure: the fraction and summation layout, their bounds, powers and indices, and some operators are not represented faithfully. The Reader preparation does not recover the two equations as two correctly bounded formula blocks. **Both selected equations fail visual fidelity acceptance (0 / 2).**

No live LaTeX reconstruction was scored. A syntactically valid KaTeX string would not prove equivalence to the original formula. Fixing reading order, preserving mathematical source structure, and adding a verified OCR/layout path remain necessary before claiming dependable equation-heavy support.

## Bounded live summary

A separate run on the same source page used `--task summary`, Claude Code `2.1.270`, requested alias `sonnet`, two provider calls and 105.9 seconds. It returned three overview claims and three section claims. All six quotations passed exact span validation (6 / 6). This was an adapter/validation run, not a second database-publication test.

Local summary result SHA-256: `1fe8a480972652d90f3f11f0b26820b93ee27c6b648996a8ac990933cce28d5b`.

Manual review found all six claims consistent with the surrounding source paragraph. However, only four claims were fully supported by their selected quotation alone (4 / 6):

| Claim | Quotation coverage |
| --- | --- |
| Overview: three-step hedging | Directly supported |
| Overview: $1.01 value and 0.8% annual return | Directly supported |
| Overview: two named models and beta decomposition | Directly supported |
| Section: decomposition, beta comparison and improved portfolio efficiency | **Incomplete:** the quote says only that there are three steps; their details are in subsequent source sentences |
| Section: cash valuation and annual return | Directly supports the numeric finding |
| Section: decomposition plus greater beta variation | **Incomplete:** the quote supports decomposition, but the dispersion comparison requires the next source sentence |

This is a citation-granularity failure for two claims, despite exact-match integrity and source-context consistency. A future improvement should require evidence covering every factual clause or shorten the claim. Current summaries remain labeled AI drafts; neither this report nor the interface promotes these claims to human-verified findings. The sample does not establish summary quality for a full paper or for Research Maps.

## Evidence navigation and recovery

A browser run used a one-page derivative of FEDS physical page four, created with `pdfseparate`, and deterministic providers. The derivative's Reader page one corresponds to original PDF page four. The run processed the public source, generated an explicitly labeled mock summary, expanded its quotation with the keyboard, and moved focus to the exact quoted Reader block. This checks navigation and citation integrity, not the quality of a generated interpretation.

Replacing this isolated source with raster image bytes caused preflight to show OCR setup guidance while retaining the previous Reader and quotation. Restoring the original public source and retrying succeeded: the Reader still contained exactly one block, and the retained summary was explicitly marked as belonging to a different Reader version. No private document, database, credential or provider response was committed.

## Priorities established by this baseline

1. Preserve reading order for multi-column PDFs and detect when extraction is insufficient.
2. Preserve table row/column structure and recognize numbered/appendix section headings.
3. Add trustworthy formula extraction and visual comparison before presenting reconstructed formulas as reliable.
4. Improve paragraph segmentation and cross-page context for translation.

The milestone delivers reproducible measurements, regression checks and documented limits. These remaining product-quality failures are not relabeled as passing tests.
